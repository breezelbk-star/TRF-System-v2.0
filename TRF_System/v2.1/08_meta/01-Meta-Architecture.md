# TRF v2.1 系统 Meta Architecture（系统元结构）

本文件用于解释 TRF 系统的“底层设计逻辑 + 模块之间的关系”，确保未来可以快速升级。

---

## 1. TRF 系统由 4 个层级构成
### （1）Core Layer —— 交易底层逻辑（不随市场变化）
包含趋势、轮动、流动性、风险、执行  
这些是永恒有效的交易结构，是 TRF 系统的“灵魂”。

### （2）Playbook Layer —— 可执行策略层（会随市场迭代）
如：  
- 半导体行情 T+0 模型  
- 抢龙头模型  
- 关键位突破模型  
- 资金异动模型  

### （3）Tools Layer —— 工具层（辅助）
如：  
- 选股公式  
- 盘口模型（情绪指标、量能指标）  
- T+0 自动化工具  
- excel 数据记录模块  

### （4）Meta Layer —— 维护层（本文件所在的部分）
用于保持系统的“生命力”。

---

Core Layer

---

## 3. TRF 系统升级原则（非常关键）
未来所有 2.2 / 3.0 升级都必须遵循：

1. **不修改 core，只扩展 playbook**
2. **保持向下兼容，避免让旧记录失效**
3. **增加数据来源（更智能）而不是增加规则（更复杂）**
4. **每次迭代必须在 changelog 中纪录升级原因**
5. **未来所有版本都必须能自动导出一份习惯化报告**

---

## 4. Meta 负责验证 TRF 系统是否“健康”
- 检查规则是否矛盾  
- 检查策略是否重叠  
- 检查工具是否过时  
- 检查日志体系是否能支持你个人的行为模式  
- 检查 Backtest 是否有偏差  

Meta layer = 系统的医生。
